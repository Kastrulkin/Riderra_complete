## Root cause

Inbound-обработчики классифицировали и валидировали ответ, но не реализовывали переход повторного уточнения, идемпотентный черновик и лимит неуспешных попыток.

## Approved fix

Добавлен единый обработчик повторного уточнения для обоих inbound-маршрутов, идемпотентный черновик с ручным одобрением, передача сотруднику после второй неудачи, API ручного перезапуска и понятный блок действий в Чатах.

**Why this is causal:** Исправление выполняется непосредственно после классификации/извлечения и создаёт недостающий переход состояния и черновик ровно в том месте, где раньше выполнение завершалось без следующего действия.
